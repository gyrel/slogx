# Rotation and log channels

`rotate.New(path, rotate.Config{})` opens an append-only file. Defaults are 8 MiB per active file, five archived files, and 64 MiB across the active file and archives. Zero selects the default; negative values are rejected. Archives are named by appending `.1` through `.N` to the path, newest first. A write that would exceed the size limit rotates first, except that an empty file accepts one oversized record intact. The total cap evicts oldest archives first after writes; an active record can itself exceed the cap. Canonical numbered archives beyond the configured count are pruned on open and before rotation.

Rotation stages the active name through a temporary rename and attempts to sync the directory after the chain changes. This is best effort: a power loss can leave a partial chain or staging file, and directory sync failures are not reported. If rotation fails, the writer keeps its existing file descriptor and appends subsequent records there until closed, while returning the rotation error. A partial chain can already have changed. Investigate the error and reopen after repairing the filesystem.

Best-effort logs may use `rotate.NewAsync(writer, capacity)` as an `io.Writer` for a standard `slog` handler. It copies each write and drops it if the queue is full; `Dropped()` atomically drains the count. `Flush()` waits for records accepted before its barrier and calls the sink's `Flush` when available. `Close()` refuses new writes, drains accepted records, flushes and closes the sink when supported. Flush and close can block on the sink. Asynchronous sink errors are reported by flush and close.

Audit records must use `rotate.NewSyncDurable(writer)`, with a sink implementing `Flush() error` or `Sync() error`. Each write is synchronous and flushes before returning; errors are returned to the caller and no records are intentionally dropped. The sink and filesystem determine actual persistence. A standard `slog.Logger` does not return handler write errors to its caller, so audit callers requiring error handling must write through an error-returning path. These writers can be passed to existing `slog` handlers; no handler adapter is needed.
